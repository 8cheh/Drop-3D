# ADR-0002：轴对称拟合与非轴对称场景的架构拆分

- **状态**：🟢 **已接受**（基于文献证据，非个人偏好）
- **日期**：2026-09-16
- **决策人**：HPIline（P1 负责人）
- **影响**：决定 P1 的全部模块边界、公开 API，以及「动态」需求如何实现

---

## 背景

P1 的补充需求是「**主要用于动态，即液滴滚动的时候也要做到动态识别**」。
直觉上这会让人以为：把静态的 Young-Laplace 拟合器跑在每一帧上就行了。

**调研结论是：这个直觉一半对、一半完全错。** 必须把两种情况严格分开。

---

## 证据

### 一、振荡/脉动的悬滴 —— 拟合器不用改

每个视频帧**仍然是一个轴对称悬滴**，所以同一个求解器逐帧跑即可，
时间域的分析（面积振幅、张力振幅、相位滞后 → 膨胀模量 E′/E″）是叠加在上层的。
已发表的振荡悬滴工作就是这么做的。

→ 这是**同一个模块的动态用法**，不是新模块。

### 二、滚动/滑移的液滴 —— 拟合器必须完全不参与

三条独立证据：

1. **商业 YL 软件在液滴被扰动后直接拒绝出值。** 这不是实现缺陷，是方法前提被破坏后的正确反应。

2. **最先进的滑移液滴论文彻底放弃了 YL 拟合。** Vieira, Jokinen, Lepikko, Ras, Zhou,
   *Through-Drop Imaging of Liquid–Solid Interfaces*, **Langmuir 40(17) (2024) 9059–9067**，
   doi:10.1021/acs.langmuir.4c00414 —— 他们改用**完整三维有限元能量最小化
   （Surface Evolver），以实测接触线形状作为边界条件**，逐面元求接触角。

3. **固着/滑移液滴从来就不是关于表面法向轴对称的。** 即使在均匀表面上，
   滑移液滴的足迹也是椭圆，长宽比实测 1.011–1.097。

**后果**：如果把轴对称拟合硬套在滚动液滴的轮廓上，拟合出来的「γ」会变成一个
**形状补偿参数** —— 它会为了让模型贴合一个它根本描述不了的形状而漂移。
得到的数字看起来正常，但已经不再对应表面张力。这正是本项目 `validity` 模块存在的理由。

---

## 决策

**把代码拆成两个模块，边界是「形状假设是否成立」，不是「静态还是动态」。**

### Module A —— 轴对称（现有代码，`drop3d.tensiometry` 等）

- 适用范围：静态悬滴、**振荡/脉动悬滴的每一帧**
- 核心：Young-Laplace 求解 + 五参数拟合 + 尺度标定 + γ + 不确定度
- 静态与动态**共用同一个求解器**，动态只是在时间轴上重复调用并加时间域分析

### Module B —— 非轴对称（待建，本 ADR 只定边界）

- 适用范围：滚动、滑移、剪切驱动、撞击铺展
- **绝不调用 Module A 的拟合器去处理轮廓**
- **把 γ 当作输入**，而不是输出
- 可用测量：接触角（前进/后退）、足迹几何与长宽比、体积、速度、高度、
  接触线形状、纵横比随时间的变化
- 若需要三维形状：以实测接触线为边界条件的约束求解（Surface Evolver 路线），
  或者最省成本的「侧视 + 45° 反射镜，单相机」（Le Grand 等的已发表做法）

### 关键单向依赖

```
Module A  ──γ──►  Module B
```

Module B 消费 Module A 的结果（单独做一次静态/悬滴测量得到 γ），
Module A 永不消费 Module B。**这个方向不能反。**

---

## 后果

1. **接口**：任何接受「轮廓」的函数都必须显式声明它假设轴对称。
   建议命名约定：`fit_axisymmetric_*` 而非 `fit_*`。
2. **拒绝路径优先**：`validity.assess` 里的 `axisymmetry` 检查（左右残差差异）
   在滚动液滴上**必须触发**。需要在合成非轴对称形状上标定它的阈值——
   目前是 `engineering` 阈值，未标定。
3. **UI/文档必须说清楚**：报告一个滚动液滴的「YL 拟合 γ」是错误用法，
   要在界面上就拦住，而不是靠用户读文档。
4. **本 ADR 不解决**：Module B 的具体实现。它需要真实滚动液滴数据才能设计和验证，
   在拿到数据之前不应开工。

---

## 被否决的替代方案

| 方案 | 否决理由 |
|---|---|
| 把 YL 拟合跑在滚动液滴的侧视轮廓上 | 前提被破坏，输出会退化成形状补偿参数而使用者无从察觉 |
| 用一个「通用三维拟合」同时覆盖两种情况 | 轴对称是三维的特例但数值上便宜得多；为滚动液滴付三维的代价会拖慢主力用例 |
| 只做静态，动态需求推给别人 | P1 明确要求动态识别，回避不是方案 |
