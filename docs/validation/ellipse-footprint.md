# 验证记录：椭圆足迹拟合（含一次结论被自己推翻）

> 日期：2026-09-16 　相关代码：`drop3d.fitting.fit_ellipse`、`drop3d.dynamics.footprint_from_contact_line`
> 相关交付物：P1 动态场景（滚动/滑移液滴的足迹几何）

## 1. 这个拟合要回答什么

滚动/滑移液滴的接触线是**椭圆**。文献实测：即使**均匀表面**上，
`L/W` 也在 **1.011–1.097**，带宽 **0.086**。
所以拟合精度必须到千分之几，**而且必须知道什么时候自己不可信**。

## 2. 三次「标准做法不能用」

### 2.1 教科书圆锥曲线拟合在**理想数据上是奇异的**

经典做法（Fitzgibbon/Pilu/Fisher, *IEEE TPAMI* 21 (1999) 476）拟合
`Ax²+Bxy+Cy²+Dx+Ey+F=0`，约束 `4AC−B²=1`。

**它在轴对齐椭圆上直接报奇异。** 实测：

```
S = DᵀD 条件数 : 1.39e16
奇异值         : [557, 226, 100, 99.5, 56.0, 0]
```

最小奇异值**恰好为 0**：点精确落在椭圆上时，`x²`、`y²`、`1` 三列
**在该样本上线性相关**。**数据越完美，公式越退化。**
旋转情形只是靠浮点舍入**碰巧**打破相关性才「能用」。

改为直接以 `(cx, cy, a, b, θ)` 参数化 + 真实几何距离的 Gauss–Newton。
初值由边界点二阶矩闭式给出（均匀参数化时协方差特征值**恰好**是 `a²/2`、`b²/2`）。

### 2.2 梯度归一化残差会把椭圆拉成一条线

`F/|∇F|` 不是距离，**拉长可以降低它**。实测：真实 aspect 1.2、噪声 0.5 px
的足迹拟合出 **aspect 146**。改用真实几何距离——对 `(P−E(t))·E'(t)=0`
做 Newton 求最近点（向量化）。

### 2.3 单起点优化会落进局部极小（这条推翻了我自己的结论）

**这是本轮最重要的一次更正。**

单起点版本在部分弧上给出灾难性结果，我当时的结论是「部分接触线
根本不可辨识」，并据此实现了一个「跨度失配」闸门。

**这个结论是错的。** 触发重新检验的是一次 CI 失败：
同样的合成数据，本机拟合出 aspect **2.28**，CI 上（numpy 2.5.3）拟合出 **1.006**。
**同一个函数、同一份数据、不同平台给出不同答案**——这不是可辨识性问题，
是**优化器落进了不同的局部极小**。

改为**多起点**（矩估计、圆形、拉长、旋转 90°）取残差最小者，并记录各分支。
结果：**之前所有「坏掉」的用例全部被正确恢复**：

| 真实弧长 | 单起点 aspect（旧） | 多起点 aspect（今） | 真值 |
|---|---|---|---|
| 300° | 1.0970 | 1.0970 | 1.0970 |
| 210° | 1.0972 | 1.0984 | 1.0970 |
| **200°** | **2.026** | **1.0988** | 1.0970 |
| **150°（圆）** | **2.28** | **1.0045** | 1.0000 |
| **150°** | **2.25** | **1.1006** | 1.0970 |

分支残差说明了原因——正确分支赢好几个数量级：

```
200° 1.097 : 1.099@1.00   1.099@1.00   1.076@8.34   2.210@13051
150° 圆    : 1.005@1.00   1.009@1.62   2.980@5023   2.000@20131
```

（记法：`aspect@RSS/最佳RSS`）

## 3. 那么**真正**的下限在哪里

多起点之后重新测（真实 aspect 1.0970，0.3 px 噪声，12 次实现）：

| 真实弧长 | bias | sd | 歧义判据触发 |
|---|---|---|---|
| 360° | 0.0003 | 0.0006 | — |
| 240° | −0.0001 | 0.0009 | — |
| 150° | −0.0001 | 0.0073 | 0/12 |
| 120° | 0.0031 | 0.0135 | 0/12 |
| 90° | 0.0190 | 0.0248 | 0/12 |
| **60°** | **0.2422** | **0.2595** | **4/12** |
| **45°** | **0.6767** | **1.0562** | **0/12** |

**结论**：下限远低于我原先说的 200°，真正的位置在 **90°–120° 之间**。

**而且歧义判据在真正需要它的时候不可靠**：60° 只有 4/12 触发，
45° **一次都不触发**——因为弧太短时**所有起点都收敛到同一个错答案**，
没有分歧可测。

> **一个恰好在最需要时失效的判据，不能当闸门。**

所以最终闸门落在**数据的直接属性**上：提取到的接触线**角度跨度 ≥ 120°**
才报 `L/W`。这是拟合之前就能知道的事，不可能被「自信地收敛到错椭圆」骗过。
120° 这个值落在 bias 仍比 0.086 带宽小一个数量级的位置。

歧义度与跨度失配**保留为辅助证据**（会在返回值里报出，也可用于诊断），
但**明确记录它们不充分**——这正是为什么要有一条基于数据本身的闸门。

## 4. 实测精度（合格区间内）

0.3 px 噪声、约 100 px 足迹：

| 真实 L/W | 拟合值 | sd |
|---|---|---|
| 1.000 | 1.0008 | 0.0004 |
| 1.011 | 1.0111 | 0.0006 |
| 1.097 | 1.0971 | 0.0006 |

无噪声时**精确到机器精度**（1e-14），包括曾经直接失败的轴对齐情形。
带宽 0.086，散布 0.0006 → **L/W = 1.011 与 1.000 可分（约 18σ）**。

## 5. 顺带修掉的一个我自己写出的缺陷

`footprint_aspect` 原本对**测量值**做硬边界比较 `1.011 ≤ ratio ≤ 1.097`，
于是一个真实值**恰好等于** 1.097 的足迹会因 ±0.0006 的噪声随机落到边界两侧，
被报成「超出均匀表面范围」——**把舍入级差异说成物理结论**。
已改为统计判据（给定 `aspect_std` 时超出 3σ 才算超出）。

## 7. 教训

> **「这个数据不可辨识」和「我的优化器没找到解」是两件不同的事，
> 而我第一次把后者当成了前者。**
>
> 发现它的不是自审，是**跨平台 CI**——同一个函数在不同 numpy 版本上
> 给出不同答案，这个信号直接指向优化器而不是物理。
> 如果 CI 只跑一个 Python 版本，这个错误会一直留在库里，
> 而且会被写成一条看起来很严谨的「已知局限」。
