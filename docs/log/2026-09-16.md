### 2. ADR-0002：轴对称 / 非轴对称拆分

调研给出一个必须现在拍板、且会渗透到整个架构的结论：
**滚动液滴上不能跑轴对称 Young-Laplace 拟合**。依据见
[ADR-0002](../decisions/0002-axisymmetric-vs-non-axisymmetric.md)。
决策是拆成 Module A（轴对称：静态 + 振荡的每一帧，同一个求解器）与
Module B（非轴对称：滚动/滑移，**永不**在轮廓上调用 YL 拟合器，γ 作为**输入**），
依赖单向 A→B。

### 3. `validity.py` 按调研重写

调研推翻了我原来的判据设计：

- **Bond 数不能预测精度**（Yang, Yu & Zuo 2017 明确指出小体积下失效），
  我却把它当成了主要条件数闸门。现在 Bo 降级为**纯求解器有效性**检查
  （超出范围前向模型本身就没意义），**精度由 Worthington 数把关**。
- **Wo 是两级闸门**：`Wo = 0.5` 是形状方程的分叉边界（Kratz & Kierfeld 2020），
  低于它多个解支共存，最小二乘可能收敛到错支——**产出的是自信的错值，
  而不是明显坏的值**，所以这是硬拒绝；`Wo > 0.1` 是工作阈值。
- 新增 Neumann 数检查，但**明确标注其数值阈值是我们自己的占位值**，
  文献只给了「Ne 比 Bo 更能预测精度」这个论断，没给阈值表。
- 新增命名错误码与计数式可靠性分级。

**这一轮没有引入任何「查不到出处就编一个」的阈值。** 查不到的，
代码注释里写明查不到。

## 遇到的问题

### 修复的真实缺陷

自审发现 4 个：

1. Worthington 检查在 `0.1 < Wo < 0.5` 区间**谎称**「也低于工作阈值 0.1」——
   报告引用了自己并不满足的数字。已改为分三支、各自说各自的事实。
2. Neumann 是软检查却用了 `REJECT_` 前缀。下游若按前缀分流，会把可用测量丢掉。
3. Neumann 的阈值出处标成了 `literature`，但那个数字**没有文献依据**，
   只有指标本身有。已改标 `engineering (threshold); literature (metric)`。
4. `residual_rms` 在拟合没给出 RMS 时**被静默省略**，报告因此显得比证据更干净。
   已改为记录为「未评估」。

测试发现 3 个：

5. `axisymmetry` 同样是软检查却用 `REJECT_NOT_AXISYMMETRIC`。这个尤其要紧——
   它正是**滚动/剪切液滴上最先触发的那一个**，也是下游最可能分支处理的编码。
6. `ERROR_CODES` 里有**两个死代码**：`branch_uniqueness`、`predicted_error`。
   前者对应的检查早已并入 Worthington 闸门，后者来自已撤下的 `MRE` 预测式。
   死代码不是无害的：处理 `REJECT_MULTIPLE_BRANCHES` 的人会以为分支唯一性正在被检查。
7. **Neumann 闸门几乎从不运行**——它要求调用方额外传一个 `(r, z)` 数组，
   而轮廓点本来就在参数里。**从不运行的闸门是装饰，不是闸门。**

设计补强 2 项：

8. 判决从两态改为三态：**「未评估」的硬闸门不再允许干净的 `accept`**。
   否则 `accept` 的含义会退化成「我碰巧测了的都过了」。
   但不拒绝——缺标定是调用的局限，不是反对该次测量的证据。
9. `thresholds={'min_worthington': ...}` 之前**覆盖无效**（闸门读的是模块常量）。
   文档承诺能改、实际改不动，比没有这个参数更糟。

> 共同点：这些都是**报告层**的缺陷，数值本身没错。
> 但对一个「分布外拒绝」模块来说，报告层就是产品本身——
> 一个说了假话的拒绝理由，和一个错误的表面张力一样有害。

## 2. 实现 Module B（`drop3d.dynamics`），35 项测试

按 ADR-0002，Module B **永不**在轮廓上调用 YL 拟合器，γ 是**输入**。
模块开头就把这条写成设计规则，所有函数签名都遵守。

实现了：Furmidge（`k` 显式）、Dunlop 精确 Fourier 力平衡、Cox–Voinov
动态接触角、毛细数、两种坡度 Bond 数约定、稳态滑移标度、足迹纵横比。
测试总数 66 → **101**。

### 三个「不编数字」的决定

**一、Furmidge 的默认 `k` 不是 1，而且永远返回范围。**

`k = 1` 假设接触线处接触角**间断**，该模型在 `t = π` 和 `t = 2π` 两处间断，
论文明确指出物理上不成立（间断意味着局部能量不平衡，与稳态滑移的假设矛盾）。
默认改用已发表的**分段线性**模型 `k = 2/π`，并且**每次调用都返回**
物理容许区间 `[0.5, 0.884]` 上的力范围与相对展宽。
只报一个数会把主要模型歧义藏起来。

`k ≥ 1` 会触发警告：文献里 `k ≈ 1` 通常是**固-液黏性阻力污染了测量**
（一般出现在较大的液滴上）。

**二、`ln(b/a)` 设为必填，不给默认值。**

Cox–Voinov 的 `θ³ − θ_s³ = ±9 ln(b/a) Ca` 里，报告给了式子但**没给这个参数的值**，
而它取决于实验系统与所采用的微观截断。给一个默认值等于**替用户偷偷选了微观截断尺度**。
所以它是必填参数，并且返回值里带一阶灵敏度（`ln(b/a)` 变 10% 时 θ 动多少）。

**三、故意不实现 Dussan 起动判据。**

转抄的公式在报告自带表格的三行上算出 **0.816 / 1.026 / 1.071**，
而同一张表写的是 **0.14 / 0.28 / 0.32**。比值是 5.83 / 3.67 / 3.35——
**非常数**（跨度 1.74 倍），所以这**不是**归一化差异或 Bond 数约定差异，
式子本身就不是表里数值所依据的那个函数。

两篇原始文献（Dussan 1985、Le Grand 2005）均闭源，无法核对。
**一个偏 3.5–5.8 倍的起动判据比没有判据更糟**，所以不实现，
并留了一个「负能力」测试锁住这个决定，防止有人以后顺手补上。

### 一处必须自己钉死的约定

Dunlop 的精确力平衡式 `2·Bo·sinα + π·C₁ = 0` 里，**`C₁` 的归一化没有定义**。
常见两种约定正好差 **2 倍**，也就是整条式子差 2 倍。

钉法：要求它在**间断极限下精确退化为 `k = 1` 的 Furmidge**——
这正是论文说这条式子所推广的对象。算下来
`C₁ = (1/π)∫₀^{2π} cosθ(φ)cosφ dφ` 满足；另一种约定会得到 `k = 1/2`，
落在有界 Fourier 模型给出的范围之外。已用解析解数值比对锁住（误差 < 1e-9）。

## 遇到的问题

### 一个藏在 API 里的单位陷阱

写 `fourier_c1(phi_deg, cos_theta)` 时，测试误把**弧度**传了进去。
结果不是崩溃，而是返回了一个**看起来很合理的错数**。

Fourier 系数按定义是**整个周长**上的积分，所以「必须覆盖完整周期」不是形式要求
而是定义要求。于是加了这个校验：跨度不足一周即报错，
顺带就把「误传弧度」这件事变成了**明确的错误**而不是一个错的数字。
半周长、弧度、点数不足，现在都拒绝。

# 同日第五轮：修掉不确定度的一个真实缺陷（并发现自己差点编数据）

## 1. 问题

调研阶段就把这条列为已知缺陷，本轮修并**实测**：

最小二乘的标准协方差 `σ²(JᵀJ)⁻¹` 假设残差独立同分布。
但我们是**几何拟合**——残差是「点到拟合曲线的距离」，
同一条轮廓上相邻点的距离**天然相关**（镜头畸变、分割偏差会整段推偏）。
正相关把非对角项加到对角线上，于是方差**偏小、误差条过小**。

## 2. 做法：用真值判定，而不是「理论上应该更好」

实现了 Newey–West sandwich `A⁻¹BA⁻¹`，其中 `B` 是 `JᵀΣJ` 的自相关一致估计。
关键是**怎么判定它到底有没有用**——所以建了两层真值：

**第一层：轮廓管线蒙特卡洛**（60 次实现，真值 ±9%）

| 残差模型 | naive | HAC |
|---|---|---|
| 独立同分布 | 0.89 | **0.95** |
| 相关（L≈5） | **1.93** | **1.21** |

（记法：经验值/预测值，**1.0 为正确，>1 表示误差条偏小**）

**第二层：线性模型的精确真值**（无模拟噪声，更强）

误差为 AR(1) 时 `Var(β̂) = (XᵀX)⁻¹XᵀΣX(XᵀX)⁻¹` 有闭式解，可以直接算：

| ρ | naive/精确 | HAC/精确 |
|---|---|---|
| 0.0 | 1.00 | 0.95 |
| 0.5 | 0.57 | 0.80 |
| 0.8 | **0.32** | **0.56** |
| 0.95 | **0.14** | **0.27** |

## 3. 这张表改变了结论

原本我准备写「HAC 修好了低估」。**数据说不是。**

- HAC 在每个 ρ > 0 上确实都不差于 naive，选它是对的；
- 但它只是**减轻**：ρ = 0.8 时只恢复真实标准误的 **56%**，ρ = 0.95 时只剩 **27%**；
- naive 在强相关下是**灾难性**的：ρ = 0.95 时误差条小 **7 倍**；
- 精度随 ρ **单调下降**，因为自动带宽只由样本量决定、**不随相关长度增长**。

于是把实测数字写进代码：轮廓残差滞后 1 自相关 ρ̂ > 0.5 时，
`parameter_covariance` 在 `info['note']` 里**自曝**这些恢复率，
并指明**该用 `bootstrap_parameters` / `monte_carlo`**——
而不是返回一个看起来很自信的小误差条。

> **一个说自己不可信的模块，比一个悄悄给出 3 倍偏小误差条的模块有用得多。**

还试过用 Andrews 自适应带宽救回来：ρ = 0.9 时它给出的 L 远超样本量（会被截断到 n−1），
失去意义。**强相关下 sandwich 本身就不够用**，这是方法边界而不是调参问题。

## 4. 差一点编出一个数字

写警告文案时，我顺手写了一个插值式：

```
max(0.0, 1.0 - rho_hat) * 100     #「HAC 恢复率」
```

它在 ρ = 0.8 时给出 **20%**。而**实测是 56%**。

这个式子是**从我的表里硬凑出来的**——表上只有 4 个 ρ 的实测点，
衰减对 ρ 并非线性，我却在写一个连续的闭式表达。
这正是我在本库其它地方一直拒绝做的事（「查不到出处就不要编一个」），
只不过这次编的是**我自己的数据**。

已改为**直接引用表中四个 ρ 的实测值**，并加测试锁住这四个数字出现在提示里。

## 5. 顺带修的性能问题

`_check_hac_exact.py` 第一次跑**超时**。原因：AR(1) 误差用
`multivariate_normal` 生成，每次抽样都要分解稠密的 150×150 协方差，是 O(n³)。
换成精确的递推 `x_t = ρx_{t−1} + z_t`（O(n)，分布完全相同）后正常。
同样的修改用在测试里，`test_uncertainty_robust.py` 从 **57 秒降到 23 秒**。

## 结果

**已验证**：`ruff` 干净；测试 101 → **115**。

**新增证据文件**：[`docs/validation/hac-covariance.md`](../validation/hac-covariance.md)，
含两张真值表和三个复现脚本的路径与耗时。
这是本库第一份**专门的验证记录**，因为这次的主张（「换一个估计量更准」）
必须靠测量而不是靠论证来支撑。

**已知局限（不粉饰）**：强相关下 HAC 仍偏低约 44%。已写进模块 docstring、
验证文档和运行时提示三处。

2. 振荡悬滴的相位滞后拟合——调研指出不加滞后项会拟合出**负的**振幅。
3. 仍等团队拍板：**许可证**、**动态场景的具体形态**、**精度目标**、
   **谁提供真实实验数据**。

# 同日第六轮：Module B 的几何（椭圆足迹），以及两次「标准做法不能用」

## 目标

滚动/滑移液滴的足迹是**椭圆**而非圆。调研给出：即使在**均匀表面**上，
文献实测 `L/W` 也在 **1.011–1.097**。要判读这个量，
拟合精度必须到千分之几，而且必须**知道什么时候自己不可信**。

## 1. 第一次「标准做法不能用」：教科书椭圆拟合在理想数据上奇异

先按 Fitzgibbon/Pilu/Fisher（*IEEE TPAMI* 21 (1999) 476）的经典做法实现：
拟合圆锥曲线 `Ax²+Bxy+Cy²+Dx+Ey+F=0`，约束 `4AC−B²=1`。

**它在轴对齐椭圆上直接报「normal equations are singular」。** 查下去：

```
S = DᵀD 的条件数 : 1.39e16
奇异值           : [557, 226, 100, 99.5, 56.0, 0]
```

最小奇异值**恰好是 0**。原因是：当点**精确落在**椭圆上时，
`x²`、`y²`、`1` 三列在该样本上**线性相关**——
也就是说，**数据越完美，这个公式越退化**。
旋转椭圆之所以「能用」，只是因为浮点舍入**碰巧**打破了那个精确相关性。

> 一个在**理想数据上最差**的拟合器，不能用来判断足迹是不是圆。

改为直接用 `(cx, cy, a, b, θ)` 参数化 + 几何距离的 Gauss–Newton。
初值由边界点二阶矩闭式给出（均匀参数化时协方差特征值**恰好**是 `a²/2`、`b²/2`）。
现在**无噪数据上精确到机器精度**（误差 1e-14），包括之前直接失败的那个轴对齐情形。

## 2. 第二次「标准做法不能用」：梯度归一化残差会把椭圆拉成一条线

几何优化需要「点到椭圆距离」。先用了便宜的 `F/|∇F|`——**灾难**：
它在噪声下把椭圆拉向**退化的线段**，因为拉长可以降低这个量。
实测：真实 aspect 1.2、噪声 0.5 px 的足迹，拟合出 **aspect 146**。

改为**真正的几何距离**：对 `(P−E(t))·E'(t)=0` 做 Newton 求最近点（向量化，几次迭代收敛）。
之后噪声下 aspect 偏差 ~0.0001、标准差 ~0.0006。

**实测精度（0.3 px 噪声，约 100 px 足迹）**：

| 真实 L/W | 拟合值 | 标准差 |
|---|---|---|
| 1.000 | 1.0008 | 0.0004 |
| 1.011 | 1.0111 | 0.0006 |
| 1.097 | 1.0971 | 0.0006 |

均匀表面带只有 **0.086** 宽，而散布是 **0.0006**——**分辨力足够**，
连 1.011 与 1.000 的差别都在 18σ 以上。

## 3. 第三次「标准做法不能用」：局部不确定度测不出全局错

接线的接触线（被遮挡、被视场截断）会怎样？实测**崩得很干脆**：

| 真实弧长 | aspect 误差 |
|---|---|
| 240° | 0.0001 |
| 210° | 0.0002 |
| **200°** | **0.93** |
| 180° | 1.30 |

但**拟合自己不知道**：它报 `ok`、RMS 很小，而且
**Jacobian 算出的 `aspect_std` 只有 0.0003——比合格的 240° 情形（0.0009）还小**。
拟合在**局部完美、全局错误**，任何基于曲率的量都看不见。

试过用「绕拟合中心的角覆盖」把关——**也不行**：坏掉的 200° 报出 244°，
与合格的 240°（237.7°）无法区分。

**最后找到的判据**：比较弧的**真实角度跨度**与它在**椭圆参数 t 中的跨度**。
拟合自洽时两者相差 ≤3°；拟合在**扭曲**这条弧时相差 18°–48°：

| 真实弧长 | aspect 误差 | 角覆盖 | **跨度差** |
|---|---|---|---|
| 240° | −0.0001 | 237.7 | **2.4** |
| 210° | 0.0002 | 207.8 | **2.3** |
| 205° | **0.417** | 221.8 | **18.1** |
| 200° | **1.004** | 243.7 | **40.0** |
| 190° | **1.255** | 244.2 | **47.6** |

阈值取 **10°**，落在最大的合格值（2.4）与最小的坏值（18.1）之间。
`EllipseFit.aspect_is_informative` 就是这条判据，并且**未知一律不算通过**。

## 4. 顺手修掉一个我自己刚写出来的缺陷

`footprint_aspect` 原本对**测量值**做硬边界比较：`1.011 <= ratio <= 1.097`。
于是一个真实值**恰好等于** 1.097 的足迹，会因为 ±0.0006 的噪声随机落到边界两侧，
被报成「超出均匀表面范围」——**把舍入级别的差异说成了物理结论**。

已改为统计判据：给定 `aspect_std` 时，只有超出带宽 `3σ` 才算「超出」，
并把 `tolerance` 一并返回。这个缺陷是被测试抓出来的，
而不是我审出来的——**测试比自审更可靠，这已经是本轮第三次证明了**。

## 结果

**已验证**：测试 115 → **132**。无噪椭圆恢复到机器精度（1e-14），
噪声下的 aspect 精度经 12–30 次重复实测。

**新增** `tests/test_geometry.py`（17 项）与 `drop3d.fitting.fit_ellipse` /
`EllipseFit`、`drop3d.dynamics.footprint_from_contact_line`。

**未验证**：仍全部是合成椭圆。真实接触线的提取（分割）尚未实现，
所以这条链路的输入端还没有接过真实图像。

## 下一步

1. 接触线提取（分割）——**需要真实图像才能验证**，见下。
2. 振荡悬滴的相位滞后拟合。
3. 团队决策仍待：许可证、动态场景形态、精度目标、实验数据来源。

# 同日第七轮：振荡悬滴的膨胀模量（把调研的论断当假设去检验）

## 做了什么

`drop3d.oscillation`（23 项测试）。逐帧 YL 拟合**不变**——每帧仍是轴对称悬滴，
同一个求解器跑；新增的只是时域分析：

```
A     = A₀ + A_a sin(ωt + φ_ins)
γ     = γ₀ + γ_a sin(ωt + δ + φ_ins)
E* = E′ + iE″ ,  E = γ_a / (A_a/A₀) ,  E′ = E cos δ ,  E″ = E sin δ
```

`φ_ins` 是**两条序列共享的拟合参数**，不是假设——面积和张力来自同一批帧、
同一条仪器链，只有液滴自身的黏弹滞后 `δ` 能把两者区分开。

## 调研的论断：对，但**有前提**——而我们的失败形态更危险

调研说：不加滞后项会拟合出**负的**振幅。我没有照抄，而是当假设去测：

**带滞后项**：注入滞后 0°–150°（远超相位回绕处），往返**精确到机器精度**。

**去掉滞后项**：失败形态**不是负振幅**，而是**面积振幅塌缩、模量爆炸**：

| 注入滞后 | A_a | γ_a | δ 拟合值 | E |
|---|---|---|---|---|
| 0° | 0.50000 | 0.40000 | 20° | 16（正确） |
| 45° | 0.35355 | 0.40000 | 65° | 22.6 |
| 90° | **0.00005** | 0.40000 | 110° | **1.8×10⁷** |

机理是滞后被 `δ` 吸收（`δ_拟合 = δ + φ_ins`），面积振幅被迫缩小以补偿相位错位。
**γ_a 反而保持正确**——所以这个失败极难察觉。

再把**正性约束去掉**才复现出调研说的负振幅：注入滞后 **150°** 时
`A_a = −0.433`、`γ_a = −0.400`，两者同时为负。

> **所以论断成立，条件是「滞后足够大」且「拟合没加正性约束」。**
> 而我们的实现**有**约束（那是调研给出的修正方案的一部分），
> 于是它给出的是一个**数值巨大但看起来正常**的模量。
>
> **受约束的失败比不受约束的失败更危险——符号不再替你报警。**
> 因此 `fit_instrument_lag=False` 会**主动警告**，而不是指望负号暴露问题。

## 一次真实返工：我的实验设计错了

测采样率影响时，第一次用**无噪声**正弦——结果 1000 帧/周期到 **12 帧/周期全部精确**，
什么也没测出来。无噪声正弦用十几个点就能精确确定。

**这不是代码错，是实验设计错：没有噪声就没有可测的东西。**
加上真实噪声重测（面积 0.02、张力 0.05 mN/m，15 次实现）：

| 帧/周期 | E 误差（1σ） |
|---|---|
| 100 | **0.68%** |
| 25 | 1.16% |
| 6 | 2.79% |

**结论**：调研那条「≥100 帧/周期」是工程规则（文献中**没有**最低采样比规定，
调研已如此标注），实测对应 E 误差约 0.68%，降到 25 帧/周期也只到 1.2%——
**规则偏保守，留了约 2 倍余量**，而这里的噪声水平还偏严苛。

## 误差条是校准的

时间序列残差天然相关，所以用 HAC sandwich（`docs/validation/hac-covariance.md`
里那套）。报出的 γ_a 标准误 vs 12 次实现的实际散布：

| 周期数 | 报出标准误 | 实际散布 | 比值 |
|---|---|---|---|
| 1 | 0.00488 | 0.00420 | 1.16 |
| 3 | 0.00287 | 0.00286 | 1.00 |
| 10 | 0.00158 | 0.00200 | 0.79 |

比值 0.79–1.17，而 12 次实现估出的标准差自身精度只有约 ±20%。
**误差条是校准的**，不是装饰。

## 顺带修的一个收敛问题

默认 `least_squares` 容差在无噪数据上让相位只精确到 ~1e-4 度，
比模型本身差得远。拟合很便宜，改成 `ftol=xtol=gtol=1e-14`。

## 结果

**已验证**：`ruff` 干净；测试 132 → **155**。
新增验证记录 [`docs/validation/oscillation-phase-lag.md`](../validation/oscillation-phase-lag.md)。

**未实现**：振荡频率上限。Cagna et al. 有专文，但调研未取得其数值，
故**不引用任何截止频率**——不编数字。

**未验证**：逐帧 `γ(t)`/`A(t)` 的产出依赖分割管线，仍需真实图像。

1. 接触线提取（分割）——需要真实图像。
2. 滑移侧的有效性降级策略（W5.3）。
3. 团队决策仍待：许可证、动态场景形态、精度目标、实验数据来源。

# 同日第八轮：**推翻自己第六轮的结论**

## 触发点：一次 CI 失败

第六轮推送后 CI 在 **py3.12 一个作业**上失败（3.10/3.11 通过）。
查日志：`test_a_truncated_circular_footprint_is_flagged_too` 失败，因为
**同一份合成数据，本机拟合出 aspect 2.28，CI 上拟合出 1.006**
（numpy 2.5.3）。

**同一个函数、同一份数据、不同平台给出不同答案。**

这个信号的含义很明确：不是可辨识性问题，是**优化器落进了不同的局部极小**。

## 我第六轮写了什么，以及为什么是错的

第六轮我测到单起点椭圆拟合在部分弧上崩得很干脆（200° 弧给出 aspect 2.05），
于是写下结论：**「部分接触线根本不可辨识」**，
并实现了一个「弧在真实角度与椭圆参数中的跨度之差」闸门，配了实测表格和测试。

**这个结论是错的。** 部分弧**可以**辨识，只是单起点优化找不到那个解。

改为**多起点**（矩估计、圆形、拉长、旋转 90°）取残差最小者后：

| 真实弧长 | 单起点（旧） | 多起点（今） | 真值 |
|---|---|---|---|
| 210° | 1.0972 | 1.0984 | 1.0970 |
| **200°** | **2.026** | **1.0988** | 1.0970 |
| **150°（圆）** | **2.28** | **1.0045** | 1.0000 |
| **150°** | **2.25** | **1.1006** | 1.0970 |

各分支的残差说明了原因——正确分支赢好几个数量级：

```
200° 1.097 : 1.099@1.00   1.076@8.34    2.210@13051     （aspect@RSS/最佳）
150° 圆    : 1.005@1.00   2.980@5023    2.000@20131
```

## 真正的下限，以及为什么闸门换了位置

多起点之后重测（真值 1.0970，0.3 px 噪声，12 次实现）：

| 弧长 | bias | sd | 歧义判据触发 |
|---|---|---|---|
| 240° | −0.0001 | 0.0009 | — |
| 150° | −0.0001 | 0.0073 | 0/12 |
| 120° | 0.0031 | 0.0135 | 0/12 |
| 90° | 0.0190 | 0.0248 | 0/12 |
| **60°** | **0.2422** | **0.2595** | **4/12** |
| **45°** | **0.6767** | **1.0562** | **0/12** |

下限远低于我原先说的 200°，真实位置在 **90°–120°** 之间。

**而歧义判据在真正需要它的时候不可靠**：60° 只 4/12 触发，45° **一次都不触发**——
弧太短时**所有起点都收敛到同一个错答案**，没有分歧可测。

> **一个恰好在最需要时失效的判据，不能当闸门。**

所以闸门改到**数据的直接属性**上：**跨度 ≥ 120°** 才报 `L/W`。
这是拟合之前就知道的事，不可能被「自信地收敛到错椭圆」骗过。
歧义度与跨度失配**降级为辅助证据**，并在代码注释里明确写出它们不充分。

## 结果

**已验证**：`ruff` 干净；测试 155 → **156**（几何 17 → 18）；
无噪椭圆仍**精确到机器精度**。
新增 [`docs/validation/ellipse-footprint.md`](../validation/ellipse-footprint.md)，
完整记录三次「标准做法不能用」与这次更正。

已**就地更正** `docs/plan/roadmap.md` 的 W5.2 相关表述；
本文件第六轮的记载**保留不改**——那是当时的真实记录，
而更正的价值恰恰在于说明「写得很严谨的已知局限」也可能是错的。

## 教训

> **「这个数据不可辨识」和「我的优化器没找到解」是两件不同的事。**
> 我第六轮把后者当成了前者，而且写成了一条带实测表格、
> 带测试、看起来很严谨的「已知局限」。
>
> 抓住它的不是自审，是**跨平台 CI**。
> **如果 CI 只跑一个 Python 版本，这个错误会一直留在库里。**

## 紧接着的第二次更正：下限从 120° 提到 240°

修完多起点后我把下限定在 120°，**推送后 CI 又失败了**——而这次失败更有价值：

| 用例 | 本机（numpy 2.2.6） | CI（**同一个** numpy 2.2.6） |
|---|---|---|
| 150° 弧 | aspect **1.1006**（bias +0.004） | aspect **1.0668**（bias **−0.030**） |

**同样的库版本，150° 弧差 0.030**——那是 0.086 带宽的**三分之一**，
**比这个测量本身要检测的效应还大**。

所以标准不是「有时准」，而是「**可复现地准**」。下限提到 **240°**：
240° 及以上在所有测过的平台上 bias < 0.001，以下则不行。
（闸门常量为 230°：覆盖度估计要减去最大间隙，标称 240° 的弧读到约 238°，
直接把闸门放在 240° 会把本该接受的情形拒掉。）

同时另一个断言也被 CI 推翻：我写的「45° 时歧义判据一次都不触发」
只是**单平台的巧合**——另一个平台上它触发出 6.9 的跨度。
改成只断言两个平台都同意的事实：**歧义判据不足以单独把关**。

> **两次更正都来自 CI，没有一次来自自审。**
> 这说明「多个 Python 版本 + 每次都真跑」不是形式主义——
> 它是这一轮唯一抓出错误的东西。
