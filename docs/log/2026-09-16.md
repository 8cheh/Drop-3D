## 结果

**已验证**（可复现，测试在 `tests/`）：

- Young-Laplace 求解器：`Bo = 0` 精确退化为单位球，误差 < 1e-8。
  这是封闭解，不是数值参考，因此同时锁住方程、符号约定、顶点处理与积分容差。
- 独立交叉验证：复现公开的 selected-plane 经验关系
  `Bo = 0.1756x² + 0.5234x³ − 0.2563x⁴`，在 `Bo = 0.05–0.40` 内误差 **< 0.4%**。
- 五参数拟合：无噪回环误差 < 0.5%；0.5 px 噪声下 < 15%；
  端到端 72.0 mN/m 合成水滴恢复误差 < 5%。
- 形状参数 P_s：数据驱动版本与精确解一致到 ~2%。

**未验证**：所有上述结果均基于**合成数据**。代码正确 ≠ 实验可行。

### 之前的教训：`Bo > 0.6` 时解退化

（承接上一阶段，记录在此以免丢失）

积分到赤道之后子午线会收窄到一个**颈缩**再重新向外扩张——那是方程的第二支解，
不是相机拍到的液滴。如果不在颈缩处终止，`r` 会发散（实测跑到 37，正常应约 1.1）。
现在求解器在「轮廓回到轴」或「切线回落到 π/2」两者先到者处终止。

另：模型的折线离散化本身是误差项。用 KD-tree 查询最近**顶点**而非最近**点**时，
无噪回环的 RMS 被钉在 0.71 px。把顶点间距按屏幕尺度绑到 0.15 px 后降到 0.043 px，
正好等于目标函数下界。

### 2. ADR-0002：轴对称 / 非轴对称拆分

调研给出一个必须现在拍板、且会渗透到整个架构的结论：
**滚动液滴上不能跑轴对称 Young-Laplace 拟合**。依据见
[ADR-0002](../decisions/0002-axisymmetric-vs-non-axisymmetric.md)。
决策是拆成 Module A（轴对称：静态 + 振荡的每一帧，同一个求解器）与
Module B（非轴对称：滚动/滑移，**永不**在轮廓上调用 YL 拟合器，γ 作为**输入**），
依赖单向 A→B。

### 3. `validity.py` 按调研重写

调研推翻了我原来的判据设计：

- **Bond 数不能预测精度**（Yang, Yu & Zuo 2017 明确指出小体积下失效），
  我却把它当成了主要条件数闸门。现在 Bo 降级为**纯求解器有效性**检查
  （超出范围前向模型本身就没意义），**精度由 Worthington 数把关**。
- **Wo 是两级闸门**：`Wo = 0.5` 是形状方程的分叉边界（Kratz & Kierfeld 2020），
  低于它多个解支共存，最小二乘可能收敛到错支——**产出的是自信的错值，
  而不是明显坏的值**，所以这是硬拒绝；`Wo > 0.1` 是工作阈值。
- 新增 Neumann 数检查，但**明确标注其数值阈值是我们自己的占位值**，
  文献只给了「Ne 比 Bo 更能预测精度」这个论断，没给阈值表。
- 新增命名错误码与计数式可靠性分级。

**这一轮没有引入任何「查不到出处就编一个」的阈值。** 查不到的，
代码注释里写明查不到。

### 4. 测试 45 → 66

新增 `tests/test_validity.py`（21 项），重点在**拒绝**这一侧，
同时锁住反向失败：闸门不能什么都拒。

Worthington 用例是按**物理自洽的实验**构造的——固定体积的水样悬滴，
反过来解出针头直径落到目标 `Wo`（0.5–6 mm，都是真实针规），
而不是硬凑一个算术上成立的数字。这样一旦公式写错，夹具自检会先失败。

## 遇到的问题

### 修复的真实缺陷

自审发现 4 个：

1. Worthington 检查在 `0.1 < Wo < 0.5` 区间**谎称**「也低于工作阈值 0.1」——
   报告引用了自己并不满足的数字。已改为分三支、各自说各自的事实。
2. Neumann 是软检查却用了 `REJECT_` 前缀。下游若按前缀分流，会把可用测量丢掉。
3. Neumann 的阈值出处标成了 `literature`，但那个数字**没有文献依据**，
   只有指标本身有。已改标 `engineering (threshold); literature (metric)`。
4. `residual_rms` 在拟合没给出 RMS 时**被静默省略**，报告因此显得比证据更干净。
   已改为记录为「未评估」。

测试发现 3 个：

5. `axisymmetry` 同样是软检查却用 `REJECT_NOT_AXISYMMETRIC`。这个尤其要紧——
   它正是**滚动/剪切液滴上最先触发的那一个**，也是下游最可能分支处理的编码。
6. `ERROR_CODES` 里有**两个死代码**：`branch_uniqueness`、`predicted_error`。
   前者对应的检查早已并入 Worthington 闸门，后者来自已撤下的 `MRE` 预测式。
   死代码不是无害的：处理 `REJECT_MULTIPLE_BRANCHES` 的人会以为分支唯一性正在被检查。
7. **Neumann 闸门几乎从不运行**——它要求调用方额外传一个 `(r, z)` 数组，
   而轮廓点本来就在参数里。**从不运行的闸门是装饰，不是闸门。**

设计补强 2 项：

8. 判决从两态改为三态：**「未评估」的硬闸门不再允许干净的 `accept`**。
   否则 `accept` 的含义会退化成「我碰巧测了的都过了」。
   但不拒绝——缺标定是调用的局限，不是反对该次测量的证据。
9. `thresholds={'min_worthington': ...}` 之前**覆盖无效**（闸门读的是模块常量）。
   文档承诺能改、实际改不动，比没有这个参数更糟。

> 共同点：这些都是**报告层**的缺陷，数值本身没错。
> 但对一个「分布外拒绝」模块来说，报告层就是产品本身——
> 一个说了假话的拒绝理由，和一个错误的表面张力一样有害。
